## What it is

`@ui-sdk/core` is a TypeScript library of UI behaviors, the layers that make up a component library. It provides building blocks for keyboard navigation, focus, selection, popups, drag and drop, and the ARIA attributes those interactions need.

You combine those pieces to build your own components.

## Let Me Show You

Here's an emoji picker. This component is not available in `@ui-sdk/react`. An agent built this component by combining behaviors from `@ui-sdk/core`.

It has everything you expect: arrow key navigation between emoji, fuzzy search with ranked matches, and screen reader announcements.

The emoji picker is built from four pieces of `@ui-sdk/core`, which work together to provide the behavior:

- **One Tab stop.** [`createRovingFocus`](./behaviors/focus#roving-focus) lets Tab enter the grid once. The arrow keys move between emoji, and the next Tab leaves it. You don't have to tab through every button.
- **Arrows that follow the layout.** [`spatialMove`](./behaviors/focus#spatial-focus) chooses the nearest emoji in the direction you press. Down still goes down when the grid fits fewer columns on a small screen.
- **Search results.** [`fuzzyScore`](./text#rank-what-someone-searches-for) ranks each emoji's name and keywords against what you type. "party" finds the party popper, and "ship" finds the rocket.
- **Announcements.** [`announce`](./platform#announcements) tells screen readers how many emoji match and which one you picked.

The picker adds the connections between them, like moving focus from the search field into the grid when you press Down.

## How It Fits Together

The picker keeps state, like the search query and the focused emoji. It has parts, like the search field, the grid and each emoji button. A **primitive** puts that state, those parts and their behaviors together in one definition.

You write the primitive once. Framework adapters render its parts in React, Vue, Svelte, Solid and Web Components. The behavior stays in `@ui-sdk/core`, and each adapter connects it to your framework.

The parts are unstyled. They expose attributes and CSS variables for styling. You can style them how you want.

## Why It Exists

Component libraries cover familiar patterns, like menus, dialogs and tabs. Your product may need a kanban board, a timeline you can scrub, or a picker made for one task.

You can build the interface, but the interactions take work. Focus needs somewhere to go when an item disappears. A drag needs a keyboard alternative. Closing a popup needs to return you to where you were.

Agents face the same problems when they generate interfaces. `@ui-sdk/core` gives you and your agents tested behaviors to build on, so each new component can reuse that work.

You still choose how the pieces fit and give the component its names, roles and instructions. The [testing kit](./testing) in `@ui-sdk/core` helps you check the result, including keyboard behavior, ARIA relationships and server-rendered attributes.

## Build Your First Component

Start with [Build a Component](./build-a-component). You'll build a toggle with one piece of state and one button, render it in your framework, and add styles.

Then [Compose Behaviors](./compose-behaviors) brings several parts together in a star rating. Connect their focus and keyboard behavior, then test how they work together.

From there:

- [Define a Primitive](./kernel/define-a-primitive) covers options, slot state and working with elements.
- [Behaviors](./behaviors) helps you find the pieces for what you're building.
- [Reference](./reference) lists the functions and types when you need the details.
